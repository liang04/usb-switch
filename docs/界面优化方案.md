# USB Switch Console 界面优化方案

> 现状：7 个 `QGroupBox` 等权重竖向堆叠在 `QScrollArea` 里，窗口 700×900。
> 判断：**问题不在"不好看"，而在信息架构** —— 最重要的「U 盘现在挂在谁身上」
> 是状态区里的一行小字，而一次性配置（远程连接表单，约 300px）与日常操作同权重常驻。

---

## 1. 诊断：现存问题清单

### A. 信息架构（严重，收益最大）

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| A1 | **7 个分区等权重**，无主次 | `main_window.py::_build_ui` 平铺 7 个 panel | 视觉无处落脚，用户每次都要重新扫一遍全部内容 |
| A2 | **首屏放不下关键操作** | 内容高约 950px，窗口 900px | 「→ Host A/B」需滚动才可见，而这是最高频动作 |
| A3 | **核心信息被降级** | 「当前主机」是 `KeyValueGrid` 的一行文本 | U 盘在哪是这个程序唯一的核心问题，却不是视觉焦点 |
| A4 | **状态分散在 4 处** | 设备灯 / 状态区 / 桥接灯 / 隧道灯 | 判断「现在能不能切」需要拼 4 个地方的信息 |
| A5 | **一次性配置与日常操作同级** | 远程面板 8 个输入框 + 6 个按钮常驻 | 配好后再也不动的表单，长期占据首屏下方空间 |
| A6 | 无状态栏 | — | 滚动到下方时，顶部状态不可见 |

### B. 视觉（中等）

| # | 问题 | 位置 | 说明 |
|---|---|---|---|
| B1 | 字号只有 13px 一档，12/15px 是零散孤例 | `theme.py` | 无字阶概念，标题与正文几乎无对比 |
| B2 | `0.5px` 描边 | `theme.py` 全部边框 | Windows 高 DPI 缩放下可能被舍入为 0 或 1px，同一界面描边粗细不一致 |
| B3 | 仅有一套浅色主题 | `THEME` 是单层 dict | 无深色模式，且 `setStyleSheet(f"color:{hex}")` 的把颜色写死在控件上，将来换主题要改 10+ 处 |
| B4 | 卡片无法表达状态 | 状态全在 10px 小圆点上 | 「当前挂载的 Host」与「空闲的 Host」卡片外观完全相同 |
| B5 | 每张卡片 16px 上边距 | `QGroupBox { margin-top: 16px }` | 7 张卡累计 112px 纯空白 |
| B6 | 只样式化了竖向滚动条 | `QScrollBar:vertical` 单独写 | 日志区 `NoWrap` 会出横向滚动条，样式与竖向不一致 |
| B7 | 无图标语言 | `switch_panel.py` 用 `→` 文本箭头凑数 | 全靠文字，辨识成本高 |
| B8 | 间距值随意 | 8 / 12 / 14 / 16 混用 | 无 4 的倍数规范，留白节奏不齐 |

### C. 交互（中等）

| # | 问题 | 位置 | 后果 |
|---|---|---|---|
| C1 | **危险操作无二次确认** | 「断开 U 盘」与普通按钮并排，仅靠红色文字区分 | 误点即断开 VBUS，可能导致挂载中的文件系统损坏 |
| C2 | **远程「卸载」无二次确认** | `remote_panel` 卸载按钮 | 误点会删掉远端 systemd unit 与脚本 |
| C3 | 无空状态引导 | 首启只在日志里写一句「点击连接设备」 | 新用户不知道从哪开始 |
| C4 | 切换过程无进度 | `set_busy` 只把所有按钮置灰 | 弹盘最坏 8 秒，期间界面像卡死 |
| C5 | 无键盘快捷键 | — | 高频操作必须用鼠标 |
| C6 | 无日志级别过滤 | `log_panel` 只有清空/复制/导出 | 排查时要在几百行里肉眼找 error |
| C7 | 危险开关缺少持续提醒的视觉强度 | 「安全弹出互锁」关闭后仅一行黄字 | 该状态会让切换不再弹盘，风险等级被低估 |

### D. 工程侧（需一并处理）

| # | 问题 | 说明 |
|---|---|---|
| D1 | `theme.py` 是被 import 的常量而非主题对象 | 加第二套配色需要重构调用方 |
| D2 | 现有 UI 测试大量引用私有属性 | `test_ui_smoke.py` 中的 `window._switch._buttons`、`window._status._grid._values[...]` 等，重构必然破坏 |
| D3 | `KeyValueGrid.set_value` 的着色不透传主题 | 颜色写进控件级 stylesheet，脱离 `THEME` |
| D4 | `_Dot` / `ToggleSwitch` / `icons.py` 内有硬编码色值 | `#cfd4db`、`#ffffff` 等散落在绘制代码里 |

## 2. 设计原则

1. **按使用频率分层，而非按功能归属分层。** 高频（看状态、切 U 盘）常驻；低频（配置、日志）收起。
2. **一个核心问题占一个视觉焦点。** 「U 盘在哪」用最大的元素回答。
3. **状态不藏在文字里。** 卡片本身承载状态（底色 + 描边 + 徽标）。
4. **危险操作必须比普通操作更难触发。** 视觉降权 + 二次确认。
5. **不引入新依赖。** 图标继续运行时绘制，QSS 继续手写，不引 QtQuick/QML 或第三方主题库。

```
├──────────────────────────────────────────────────────┤
│ U 盘连接                          更新于 10:41  [刷新]  │
│ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐    │

│ │ ● VBUS 已接通 │ │ ○ VBUS 断开  │ │ 两路均断电    │    │  常驻
│ │ ● 检测 已插入 │ │ ○ 检测 无    │ │              │    │
│ └──────────────┘ └──────────────┘ └──────────────┘    │
├──────────────────────────────────────────────────────┤
│ ▸ 桥接服务   本地 8737 · 远程 admin@192.168.0.1  [运行中]│
│ ▸ 选项      安全弹出 开 · 开机自启 开 · 关闭到托盘 开     │  折叠
│ ▸ 日志      10:41:02 切换完成：已切换到 Host A   [展开]  │
├──────────────────────────────────────────────────────┤
│ ● 设备 已连接 │ ● 主机 Host A │ ● 本地桥接 │ ● 隧道     │  28px
└──────────────────────────────────────────────────────┘
```

首屏高度约 480px（对比现状 950px），**三件关键信息不滚动即可见**。

### 3.1 Hero 卡片的状态表达

| 状态 | 底色 | 描边 | 徽标 | 副文本 |
|---|---|---|---|---|
| 当前挂载 | 蓝 50 | 蓝 600 / 2px | `当前` | `VBUS 已接通` `检测位 已插入` |
| 已连接但非当前 | 白 | 中性 / 0.5px | — | `VBUS 断开` `检测位 无` |
| 检测到设备但未接通 | 白 | 中性 / 0.5px | — | `VBUS 断开` `检测位 已插入` |
| 切换中 | 蓝 50 | 蓝 600 / 2px + 进度条 | `切换中` | 步骤名（弹出 U 盘 / 下发命令 / 等待应答） |
| 不可用（BLE 未连） | 白 | 中性 | — | 整体降透明度至 50% |

### 3.2 折叠区规则

- 默认状态：**全部折叠**，每行右侧给一行摘要（已配置/运行状态/最后一条日志）。
- 展开状态持久化到 `config.json` 的 `window.expanded_sections`，下次启动还原。
- 有**异常**的分区自动展开一次并高亮标题（例如桥接服务异常、远程安装失败），正常后恢复折叠。
- 折叠标题左侧用 CSS 三角形旋转 90° 指示开合，不额外引入图标资源。

## 4. 视觉规范 v2

### 4.1 设计令牌

```python
# 字阶（现状只有 13px 一档）
FONT = {
    "hero":    20,   # Hero 区标题
    "title":   15,   # 分区标题
    "body":    13,   # 正文与控件
    "caption": 12,   # 次要说明
    "micro":   11,   # 徽标、状态栏
}

# 间距（现状 8/12/14/16 混用）
SPACE = {"xs": 4, "sm": 8, "md": 12, "lg": 16, "xl": 24}

# 半径
RADIUS = {"card": 12, "control": 6, "pill": 99}
```

### 4.2 颜色令牌改为双套

现状 `THEME` 是单层 `dict[str, str]`，只够一套浅色。改为按语义分组、浅深两套：

```python
@dataclass(frozen=True)
class Palette:
    bg: str            # 页面底色
    surface: str       # 卡片底色
    surface_alt: str   # 次级卡片 / 状态栏
    border: str        # 默认描边
    border_strong: str # hover 描边
    text: str
    text_muted: str
    text_faint: str
    # 每个语义色给「前景 + 浅底 + 描边」三档，卡片才能表达状态
    success: str; success_bg: str; success_border: str
    warning: str; warning_bg: str; warning_border: str
    danger:  str; danger_bg:  str; danger_border:  str
    accent:  str; accent_bg:  str; accent_border:  str
    idle:    str
```

配套改动：
- 所有 `setStyleSheet(f"color: {THEME[...]}")` 改为设置**动态属性**（`setProperty("state", "success")`）+ QSS 属性选择器，颜色由样式表统一决定，主题切换自动生效。
- `_Dot` / `ToggleSwitch` / 日志着色从 `THEME` 取值改为从当前 `Palette` 取，`icons.py` 的硬编码 `#ffffff` 一并收敛。

### 4.3 描边与层级

- 描边统一为 `1px`（高 DPI 下稳定），颜色用 `border-tertiary`（15% 透明度）。
- 层级优先用**底色差**而非描边：页面 `bg` → 卡片 `surface` → 次级 `surface_alt`。
- 取消 `QGroupBox` 的 `margin-top: 16px`，改由布局的 `SPACE["lg"]` 统一控制；折叠区用发丝分隔线，不用卡片。

## 5. 交互规范

### 5.1 危险操作二次确认

| 操作 | 确认方式 | 文案要点 |
|---|---|---|
| 断开 U 盘 | 模态对话框 | 说明「两路 VBUS 将断电」「若无挂载则无损」，提供取消为默认按钮 |
| 卸载远程桥接 | 模态对话框 + 需勾选 | 说明将删除远端 unit 与脚本、保留日志、需要重装 |
| 关闭安全弹出互锁 | 不做对话框，但改为**醒目警示条** | 现状只有一行黄字，强度不足 |

二次确认的开关（「不再提示」）**不提供** —— 这两个动作频率极低，每次确认的成本可以忽略。

### 5.2 快捷键

| 组合 | 动作 |
|---|---|
| `Ctrl+1` / `Ctrl+2` | 切到 Host A / Host B |
| `Ctrl+0` | 断开 U 盘 |
| `Ctrl+R` | 刷新状态 |
| `Ctrl+L` | 展开日志并聚焦 |
| `Ctrl+,` | 展开选项 |
| `Esc` | 收起全部折叠区 |

### 5.3 空状态与进度

- **首次启动**（无历史配置）：Hero 卡片区显示引导态 —— 「先连接设备」，切换卡片降透明度，顶栏「连接设备」按钮加脉冲高亮（一次，不循环）。
- **切换中**：被点卡片显示三段式进度（`弹出 U 盘 → 下发命令 → 等待应答`），其余卡片降透明度且不可点。
- **切换失败**：失败卡片转为红色底，点击可展开原因，日志区自动展开并滚到该条。

### 5.4 日志

- 顶部加级别过滤 chip：`全部 / 信息 / 警告 / 错误`，默认 `信息`（隐去 debug）。
- 折叠态显示最后一条；展开后固定高度 220px，不再与配置区争空间。
- 切换成功/失败时自动展开日志（可关闭）。

| 阶段 | 内容 | 影响文件 | 可独立交付 |
|---|---|---|---|

| **P2** | 交互补强：二次确认、快捷键、空状态、切换进度、日志过滤 | `main_window.py`、各 panel、新增 `ui/dialogs.py` | ✅ |

### 6.1 P0 是收益最大的一步

只做 P0 就能解决 A1–A6 全部问题，且**不碰配色**，视觉风险为零。建议先做 P0、看实际效果，再决定 P1 的配色方向。

### 6.2 回归风险

现有 `tests/unit/test_ui_smoke.py` 中有约 20 处直接访问私有控件：

```python
window._switch._buttons[Host.A]
window._status._grid._values["当前主机"]
window._remote._creds
```

P0 的重构会让其中一部分失效。处理策略：

1. **保留 `SwitchPanel` / `StatusPanel` 的公开方法与信号**（`set_enabled` / `set_current` / `apply` / `reset`），只改内部实现 —— 这样多数测试无需改动。
2. 新增面板（Hero、状态栏）的测试**只通过公开接口**（signal 与 setter）断言，不再触碰私有属性。
3. 每阶段结束跑一次真实入口的 headless 装配验证 —— 本项目已多次证明单元测试抓不到装配期问题。

## 7. 明确不做

| 不做 | 理由 |
|---|---|
| 引入 QtQuick / QML | 会放弃现有全部 Python 侧逻辑（`core/` 三层架构是项目最有价值的部分） |
| 引入第三方主题库（如 Qt-Material） | 增加打包体积与依赖，且与现有 QSS 冲突 |
| 引入 SVG/图标字体资源 | 现有 `icons.py` 运行时绘制已够用，且避免了打包资源路径问题 |
| 重做托盘的交互模型 | 托盘已可用，本次只同步状态栏的配色令牌 |
| 动画框架 | 只用 `QPropertyAnimation` 做折叠展开，不引额外依赖 |

## 9. P0 实施记录（已完成）

改动落地情况，以及与上面方案的**有意偏离**：

| 项 | 方案 | 实际 | 为什么 |
|---|---|---|---|
| 折叠展开动画 | `QPropertyAnimation` 动画 | **不做动画**，直接显示/隐藏 | 内容里有多处 `wordWrap` 标签，高度受 `heightForWidth` 影响，动画中途容易截断；桌面应用里快照式开合反而更利落 |
| 异常分区行为 | 自动展开并高亮 | **只自动展开一次**，之后由用户控制；标题常驻标红 | 每 5 秒的状态轮询都把用户正在看的内容顶走，比不展开更烦人 |
| 分区外观 | 卡片（白底 + 圆角 + 描边） | **平铺白条 + 发丝分隔线**，内容区去掉了 `QGroupBox` 边框 | 分区头本身已是一行，再套一层卡片就成了「框中框」，视觉重量翻倍 |
| 快捷键 | P2 再做 | **P0 一并做了** | 成本极低（`QShortcut` 四行），且手册里会写到 |
| 配置备份 | 无 | **新增 `config.json.bak`** | 改版过程中真的把用户配置弄丢过一次，见 §10 |
| 远程「卸载」二次确认 | P2 | **未做**，仍是 P2 | 本次只做了「断开 U 盘」的确认 |

顺带产出的东西：

- `tests/unit/test_ui_smoke.py` 新增 20 条回归，覆盖四层结构、折叠持久化、
  卡片状态、状态栏联动、空格键可用性、危险操作闸门、内容溢出边界。
- `docs/用户手册.md` §3 与 §7.1 已重写为新的版面与快捷键说明。

## 10. 一次真实事故（务必记住）

改版期间我用一个临时验证脚本建了 `MainWindow(AppConfig())` —— 传入的是**默认配置**，
而 `shutdown()` 会把内存里的配置落盘。结果：`%APPDATA%` 下已配好的远端主机
（IP / 用户名 / 密码密文）被一份空白配置覆盖了。

三条结论：

1. **任何构造 `MainWindow` 的脚本，必须先设 `USBSWITCH_DATA_DIR` 指向临时目录。**
   `selftest.py` 的 `_check_gui` 就是这么做的，临时脚本必须照做。
2. 已加 `tests/unit/test_ui_smoke.py::test_opening_gui_does_not_touch_remote_config`
   把「开一次 GUI 不会弄丢配置」钉死。
3. 已加 `config.json.bak` 作为兜底 —— 这类事故以后至少是可恢复的。

## 11. 追加改动：远程配置搬进独立窗口

用户在使用新版界面时提出的：「远程桥接服务配置不在主窗口显示，点击按钮弹出
新窗口进行配置」。这条批评很准 —— 那张表单有 10 个输入框，属于一次性配置，
却和「切换 U 盘」争主窗口面积。

| 项 | 改法 |
|---|---|
| 新文件 | `ui/remote_config_dialog.py`：`RemoteConfigDialog`（模态） |
| `RemotePanel` | 表单整块移出，只剩「目标摘要 + 配置…按钮 + 三盏灯 + 六个操作按钮 + 一行提示」 |
| 分区高度 | 约 600px → **约 180px** |
| 主窗口 | `open_remote_config()`：`exec()` 打开，单例（同时只允许一个），关窗后立刻同步隧道并刷新摘要 |
| 测试 | 表单用例搬到新的 `tests/unit/test_remote_config_dialog.py`，测试跟着拥有该行为的控件走 |

配置语义沿用主窗口既有的「改一次存一次」，所以窗口底部是「完成」而非「取消」
—— 它不承诺回滚，也就不会骗人。

### 过程中发现并修掉的两个真问题

**1. 「本机端口」永远无法编辑（存在已久的 bug）。**
它原先放在「连接参数」这个 `QGroupBox` 里，而那一组在「远程」模式下会整体
`setEnabled(False)`；子控件继承父控件的禁用状态，于是本机模式下被这一组禁掉、
远程模式下被它自己那一行禁掉 —— 两头都改不了。现在把它移出该分组，与
「角色 / 桥接类型」同排。有回归测试。

**2. 我的一个过度设计（自己写的，自己删）。**
第一版把操作按钮绑定到 `RemoteBridgeConfig.validate()`，配置不完整就整体置灰。
但这套判据比现实更严：它要求「私钥认证必须填路径」，而 paramiko 在没路径时会
回退到 agent / 默认密钥，**实测照样连得上**。用一条过严的判据锁死按钮，会把
本来能用的配置堵住。改回「配了远程角色就允许操作 + 点击时给具体错误」，
提示行保留黄色警告但不禁用。

### 顺带修掉的一个逐键副作用

配置窗口是逐键提交的（`textEdited` → `configEdited` → 持久化 + 同步隧道）。
原实现每次编辑都立刻重建隧道 —— 输入一个 IP 地址会建拆十几次 SSH 连接。
现在隧道同步走 800ms 防抖，关窗时立刻补做一次。
