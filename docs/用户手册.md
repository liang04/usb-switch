# USB Switch Console 用户手册

一枚 U 盘在**两台主机**之间切换，由 ESP32-C3 通过蓝牙控制，切换前自动在操作系统
层面安全弹出 U 盘。

---

## 1. 系统组成

```text
┌──────────────┐  BLE   ┌───────────┐  GPIO   ┌──────────────┐
│ USB Switch   │◄──────►│ ESP32-C3  │────────►│ CH442E +     │
│ Console(本程序)│       │  固件     │         │ SY6280 ×2    │
└──────┬───────┘        └───────────┘         └──────┬───────┘
       │ HTTP                                        │ USB
       ▼                                             ▼
┌──────────────┐                            ┌──────────────┐
│ 桥接服务      │  「安全弹出 U 盘」的执行端  │   U 盘       │
│ 本机 / 远端   │                            └──────────────┘
└──────────────┘
```

三个概念要分清：

| 概念 | 是什么 |
|---|---|
| **切换器（硬件）** | ESP32-C3 + 数据/电源开关板，负责把 U 盘的数据线与电源接到 A 或 B |
| **桥接服务** | 跑在**每台主机**上的小程序，负责在那台主机的操作系统里安全弹出 U 盘 |
| **本程序** | 上位机界面：连蓝牙、发切换命令、管桥接服务、显示状态 |

**为什么必须有桥接服务**：ESP32 只能控制电气连接，无法代替操作系统卸载文件系统。
如果在 U 盘仍被挂载时直接切走供电，文件系统会损坏。所以切换前必须先让「当前握着
U 盘的那台主机」把它安全弹出——这就是桥接服务的唯一职责，也是整个系统的安全语义。

## 2. 安装

### 2.1 使用打包版（推荐）

1. 把 `USB Switch Console` 整个目录拷到目标机器（**必须整个目录一起拷**，
   不能只拷 exe）。
2. 双击 `USB Switch Console.exe`。

不需要预装 Python，也不需要管理员权限。

> 建议放在固定位置（例如 `D:\Tools\USB Switch Console\`）再启用开机自启。
> 换位置后要重新勾一次自启，因为注册表里存的是绝对路径。

### 2.2 从源码运行

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e .[dev]
.venv\Scripts\python.exe -m usbswitch
```

需要 Python 3.11+。

### 2.3 硬件准备

固件烧写与接线见仓库 `README.md` 和 `docs/ESP32-C3_实际电路连接与控制设计.md`。
上位机这边只需要：ESP32-C3 已上电、电脑蓝牙已打开。

## 3. 界面

版面按**使用频率**分四层，而不是按功能归属平铺：

| 层 | 内容 | 是否常驻 |
|---|---|---|
| **顶栏** | 蓝牙连接状态、扫描 / 连接按钮 | 常驻（不随滚动移动） |
| **U 盘连接** | 三张大卡片：Host A / Host B / 断开。每张卡片直接标出该路 VBUS 通断与检测位，当前挂载的那张会高亮并带「当前」徽标 | 常驻 |
| **折叠区** | 设备状态详情、桥接服务、远程桥接服务、选项、日志。每个折叠行右侧有一行**摘要**，收起时也能看到关键状态 | 点标题展开/收起 |
| **状态栏** | 设备 / 当前主机 / 本地桥接 / 远程隧道，四个指示灯 | 常驻（窗口最底部） |

这样安排的原因：最常做的事是「看 U 盘现在在哪」和「把它切过去」，这两件事
不滚动就应看得见；而远程连接参数配好之后基本不再改动，收起来即可。

折叠区的开合状态会记住，下次启动还原。若**桥接服务异常**，该行会自动展开一次
并把标题标红——只展开一次，之后仍由你控制。

卡片上的 `—` 表示**尚未取到数据**，不是「无」。断开连接后卡片与状态栏都会被清空，
不会残留上一次的值。

状态栏最右侧有一行**构建身份**，例如 `v0.1.0 · 构建 09-18 12:47`。它回答的是
「我现在跑的是哪一版」，鼠标悬停能看到完整信息。**看不到这一行，就说明你跑的是
旧版本程序**——见 §9.9。

按 `Ctrl+1` / `Ctrl+2` 切到 Host A / B，`Ctrl+R` 刷新状态——见 §7.3。

## 4. 切换 U 盘（日常使用）

### 4.1 第一次使用

1. 确认**两台主机**上的桥接服务都已就绪（本机看「桥接服务」区，远端看
   「远程桥接服务」区）。
2. 点「连接设备」，选择 `USB-Switch`。
3. 连上后会**自动查询一次状态**，状态区随即填充。

### 4.2 切换流程

点 `→ Host B` 之后发生的事：

```text
1. 在当前主机上安全弹出 U 盘（该主机的弹出锁启用时）
      ├─ 锁未启用    → 跳过弹出，记一条警告，继续
      ├─ 成功        → 继续
      ├─ 桥接不可达  → 中止，提示「无法安全弹出，已阻止切换」
      └─ 弹出失败    → 中止，给出具体原因（占用 / 卷脏位）＋ 处理办法
2. 经 BLE 下发切换命令
3. 等待固件回执（2 秒）
      ├─ OK: host=B  → 更新界面
      └─ 超时        → 报「结果未知」，并自动查一次真实状态
```

**安全弹出失败一律硬中止**，不会「先切了再说」。此时 U 盘仍挂载着，
断电切换会损坏文件系统——这正是本系统要防的事故。唯一例外是**该主机的弹出锁
未启用**（桥接服务没起 / 远程没配），此时没有可发的弹出请求，跳过并告警。

### 4.3 安全弹出锁（按主机派生，不能手动开关）

切换前是否强制安全弹出，由**每个主机各自的锁**决定，而锁的状态是**派生的**：

| 主机 | 角色（固定） | 锁的判据 | 怎么开 | 怎么关 |
|---|---|---|---|---|
| Host A | 本机（Windows） | 本机桥接服务是否**已启动** | 点「桥接服务 → 启动」 | 点「停止」 |
| Host B | 远程（Linux） | 远程桥接是否**已配置**（填了 IP / 主机名） | 在配置窗口填地址 | 清空地址 |

- **锁启用** → 切换前必须在该主机上成功弹出，否则**中止切换**。
- **锁未启用** → 跳过该主机上的弹出并记一条警告，**但切换照常执行**。

为什么这样设计：桥接服务没启动（或远程没配地址）时，弹出请求根本无处可发，
若仍然硬中止，用户就再也切不动 U 盘了。允许「服务在跑 = 强约束，服务没跑 =
不约束」，比一个全局开关更贴近真实拓扑。

两把锁的当前状态在主窗口的「选项」分区摘要里常驻显示，
`Host A 关 · Host B 开` 这样的写法即使分区折叠也看得到。

## 5. 本机桥接服务

「桥接服务」区：

- **启动 / 停止**：服务随程序生命周期，退出时自动停止、端口自动释放，
  不会残留后台进程。**本服务还决定 Host A 的安全弹出锁**——停着时切换不会
  在本机弹出 U 盘（见 4.3）。
- **端口冲突**：默认 8737。若起不来，日志会说明原因——
  - `WSAEACCES(10013) 拒绝访问`：端口被别的程序**独占**绑定了（代理、VPN、
    安全软件常占通用端口），或落在 Windows 保留区间内。
  - `WSAEADDRINUSE(10048) 已被占用`：已经有程序在用它。
- **改端口**：在配置窗口改「本机端口」，再点「启动」即按新端口监听，
  **不需要重启程序**。

> 角色是固定的：**Host A 恒为本机（Windows）**，**Host B 恒为远程（Linux）**。
> 本机桥接服务永远属于 Host A，端口也就只有这一处。

## 6. 远程（Linux）桥接

**Host B 固定就是这个角色**。配置好之后 Host B 的安全弹出锁才会启用（见 4.3）。

### 6.1 配置

配置表单**不在主窗口里**。展开「远程桥接服务」分区，你会看到一行目标摘要和
一个「配置…」按钮 —— 点它弹出独立的配置窗口。

这样做是因为这张表单有 10 个输入框，属于一次性配置，却在主窗口里和「切换 U 盘」
争面积。搬走后主窗口的该分区从约 600px 压到约 180px，只剩状态与操作。

配置窗口里的字段：

| 字段 | 说明 |
|---|---|
| 本机端口 | 本机桥接服务（Host A）监听的端口，默认 8737 |
| IP / 主机名 | 远端地址（Host B） |
| **SSH 端口** | SSH 管理通道，默认 22 |
| 用户名 / 密码 | SSH 登录凭据（也支持私钥） |
| **桥接端口** | 远端桥接服务监听的 HTTP 端口，默认 8738 |
| 经 SSH 隧道访问 | 默认开启，见 6.3 |
| 隧道端口 | `自动`（推荐）或固定端口 |
| 别名 | 仅用于显示 |

> ⚠️ **「SSH 端口」和「桥接端口」是两个完全独立的端口。**
> 填反了症状很像「网络不通」，排查代价很高。所以它们刻意做成两个输入框。

**配置是「改一次存一次」的**，所以窗口底部是「完成」而不是「取消」——
它不承诺回滚，也不会骗你。

窗口底部的提示行会实时告诉你「将要连到哪里」，字段有缺漏时会标红指出**具体**
是哪一项。回到主窗口后，分区里也会留一行警告（黄色），但**不会禁用按钮**——
把「缺一个字段」这种可修复的状态变成「点击无反应」，比让用户看到一次明确的
失败更糟。

密码用 Windows DPAPI 加密后存放，配置文件里**没有明文**。界面回填时只显示
「已保存（留空则不修改）」，不会回显明文。

### 6.2 安装 / 启动 / 停止 / 卸载

点「测试连接」先确认 SSH 与环境（只读，不改远端）。日志会报出远端情况：
python3 版本、是否有 systemd、是否配了免密 `umount`。

然后「安装」——它会：

```text
1. 上传 linux_bridge.py → ~/.local/bin/usb_switch_bridge.py
2. 写 systemd user unit → ~/.config/systemd/user/usb-switch-bridge.service
3. systemctl --user enable --now
4. loginctl enable-linger（保证用户登出后服务不被杀）
5. 验证 /status
```

无 systemd 的老发行版自动降级为 `nohup` + PID 文件。

四个动作都**幂等**：重复安装、重复卸载、卸载一个本来就不存在的服务都不会报错。
卸载会**保留日志文件**（`~/.local/state/usb-switch-bridge.log`）。

### 6.3 关于 SSH 隧道（默认开启）

很多设备（尤其边缘网关、路由器）的防火墙**只放通 22/80/443**，桥接端口进不来。
实测一台 Robustel 边缘网关就是如此：设备上服务运行正常、设备本机
`curl 127.0.0.1:8738/status` 也正常，但从 Windows 直连 8738 被挡。

所以远端桥接默认**经 SSH 隧道访问**：把远端 `127.0.0.1:<桥接端口>` 映射到本机一个
自动分配的端口，再从本机访问。好处：

- **不需要改设备配置**；
- 无鉴权的桥接 HTTP 服务不必暴露在网络上。

关掉这个开关就会直连远端 `http://<IP>:<桥接端口>`——那种情况下远端防火墙必须
放通该端口。面板的提示行会明确告诉你**当前会连到哪一个地址**。

隧道断开后会自动退避重连（3 秒 → 30 秒）。

### 6.4 三层指示灯

「远程桥接服务」区有三个独立的灯，它们**互不等价**：

| 灯 | 含义 |
|---|---|
| **SSH** | 管理通道是否可达。只在点「测试连接 / 刷新」时才探测（SSH 开销大） |
| **SSH 隧道** | 本机端口是否已映射到远端回环 |
| **桥接服务** | 远端的 HTTP `/status` 是否在线 |

典型组合：

- SSH 绿 + 隧道绿 + 桥接红 → 服务没装或没启动，点「安装」；
- SSH 绿 + 隧道红 → 检查凭据或远端 SSH 配置；
- 三个全绿 → 可以切换了。

### 6.5 免密 umount（需要你手工做）

Linux 上 `umount` 需要 root。本程序**不会**替你改 `/etc/sudoers`——那是特权且
高风险的改动（写坏会导致那台机器连 `sudo` 都用不了），而 SSH 非交互会话也没法
安全地输入 sudo 密码。

程序只**检测**是否已配置，没配时在日志里给出这条命令，由你自己执行：

```bash
echo '<用户名> ALL=(ALL) NOPASSWD: /bin/umount' | sudo tee /etc/sudoers.d/usb-switch
sudo chmod 0440 /etc/sudoers.d/usb-switch
sudo visudo -c
```

不配也能用，但**远端有 U 盘挂载时卸载会失败**，切换会被中止。

## 7. 托盘与开机自启

- **关闭窗口** = 收进托盘（可在「选项」里改成直接退出）。程序继续运行，
  切换功能保持可用。
- **双击托盘图标** = 显示/隐藏主窗口。右键菜单可切换 Host、开关自启、退出。
- **开机自启**：写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，
  不需要管理员权限。启用后开机静默进托盘，不弹窗口。

写入后会**回读校验**；若被组策略或安全软件拦截，日志会说明，界面也会回退到
实际状态。

程序是**单实例**：重复启动不会开第二个窗口，而是把已有窗口拉到前面。
（两个实例会争抢蓝牙设备与桥接端口，必须避免。）

## 8. 文件位置

| 内容 | 路径 |
|---|---|
| 配置 | `%APPDATA%\USBSwitchConsole\config.json` |
| 配置备份 | `%APPDATA%\USBSwitchConsole\config.json.bak` |
| 日志 | `%APPDATA%\USBSwitchConsole\logs\` |
| 崩溃转储 | `%APPDATA%\USBSwitchConsole\crash\` |
| 主机密钥记录 | `%APPDATA%\USBSwitchConsole\known_hosts` |

每次保存前会把上一版留成 `config.json.bak`。配置被改坏（或你改了想反悔）时，
把 `.bak` 改名回 `config.json` 即可 —— 里面存着一整台远端主机的连接参数
与加密后的密码，值得留这一份。

配置里的密码字段是 DPAPI 密文（`dpapi:AQAA…`），**搜不到明文**。

日志面板的「导出…」会把当前日志存成带时间戳的文件，「日志目录」直接打开上面
那个目录——反馈问题时把日志一并附上即可。

## 9. 故障排查

### 9.1 扫描不到设备

1. 确认 ESP32-C3 已上电（板载指示灯闪烁）。
2. 确认电脑蓝牙已打开；关掉再打开蓝牙开关后重试。
3. 设备名应为 `USB-Switch`。若被别的程序占着（手机 App、网页面板），先关掉。

### 9.2 连上后状态区一直是 `—`

正常情况下连接成功后会立即自动查询一次。若长时间不动：

1. 点「刷新状态」看是否有回执；
2. 看日志里的固件报文。若报「服务发现失败」，关闭再打开蓝牙开关后重连
   （这是 Windows GATT 缓存损坏的典型症状）。

### 9.3 U 盘弹不出来

**先看日志给出的原因**，它已经做了区分。三个常见情况：

**(a) 卷被标记为「已损坏」（脏位）** — 最常见，也最容易被误诊成「被占用」。

```
F: 卷健康状态为 Warning，通常意味着上一次没有正常卸载（脏位被置位），
Windows 会拒绝弹出这类卷。请用管理员命令行执行 chkdsk F: /f /x 清除标记后重试。
```

按提示执行即可（`/x` 表示强制卸载；不加它 `chkdsk` 会卡在交互提示上）。
脏位几乎总是**上一次硬切换**造成的——在挂载状态下被切走了供电。

**(b) 卷正常但仍弹不出** — 确实有进程占用。关掉资源管理器里打开该盘的窗口、
退出可能正在读写它的程序（杀软扫描、索引服务）后重试。

**(c) 提示「无法打开卷」** — 卷还没挂载完。等一两秒再试；程序本身也会重试。

### 9.4 本机桥接服务起不来

看日志里的错误码：

| 错误 | 含义 | 处理 |
|---|---|---|
| `WSAEACCES(10013)` 拒绝访问 | 端口被别的程序**独占**，或落在 Windows 保留区间 | 用 `netstat -ano \| findstr :8737` 查持有者；或换端口。也可用 `netsh int ipv4 show excludedportrange protocol=tcp` 看保留区间 |
| `WSAEADDRINUSE(10048)` 已被占用 | 已有程序在用 | 查持有者或换端口 |

换端口后重新点「启动」即生效。

### 9.5 远端装不上 / 状态一直离线

按顺序查：

1. **「测试连接」报错** → 看日志里的分类提示：
   - 「认证失败」→ 用户名/密码/私钥不对；
   - 「无法连接 / 超时」→ 对方没开机、网络不通，或**把桥接端口填到了 SSH 端口上**；
   - 「主机密钥与记录不符」→ 见 9.6。
2. **SSH 通了但桥接离线**：
   - 服务没装 → 点「安装」；
   - 装了但没起 → 点「启动」；
   - 起来了但 `http_online` 仍为红 → **远端防火墙没放通桥接端口**。
     打开「经 SSH 隧道访问」即可绕开（默认已开）。
3. **装了但切换时提示无法安全弹出** → 远端没配免密 `umount`，见 6.5。

### 9.6 主机密钥与记录不符

提示会给出文件路径（`%APPDATA%\USBSwitchConsole\known_hosts`）。这代表对方的主机
密钥**和你上次连的机器不一样**——可能是重装了系统、换了设备，也可能中间有人
截获。**先核实**，确认无误后删掉该文件里对应的那一行再重试。

程序只使用自己这一份信任库，不会去读你 `~/.ssh/known_hosts`。

### 9.7 切换时提示「结果未知」

命令发出去了但 2 秒内没收到固件回执。程序会自动再查一次真实状态并更新界面，
按刷新后的状态为准即可。频繁出现时检查蓝牙信号（远离金属、缩短距离）。

### 9.8 想彻底重置

1. 退出程序（托盘右键 → 退出）；
2. 删除 `%APPDATA%\USBSwitchConsole\`；
3. 重新启动，重新配置。

### 9.9 界面没变 / 改了没反应（跑的是旧构建）

**症状**：明明改过代码（或别人告诉你有新版），双击打开后界面还是老样子，
程序也不报任何错。

**原因**：你双击的 exe 是旧的。源码改动不会自动进到已经打好的包里 ——
**必须重新执行打包**。

**怎么确认**：

1. 看**状态栏最右侧**有没有 `vX.Y.Z · 构建 MM-DD HH:MM` 那一行。
   没有 → 你在跑改版前的旧产物。
2. 看构建时间对不对。`dist\USB Switch Console\USB Switch Console.exe`
   的文件修改时间就是构建时间，与状态栏那行应当一致。
3. 命令行跑一次自检，它会直接把这个问题指出来：

   ```bat
   "dist\USB Switch Console\USB Switch Console.exe" --selftest --json out.json
   ```

   若报告里 `build 身份 / 是否落后于源码` 这一项失败，说明**产物落后于源码**，
   报告里会写清楚差了几个文件。

**怎么办**：按 §10.1 重新打包。

> 打包前必须先退出正在运行的实例，否则 exe 被占用、替换会失败。

## 10. 给开发者：打包与自检

### 10.1 打包

> ⚠️ **改了任何 `src/usbswitch/` 下的代码，都必须重新打包才能生效。**
> 开发态（`python -m usbswitch`）跑的是源码，随手改随手生效；但打包产物是一份
> **快照**，不会跟着源码变。这两者不符时程序不会报错，只会让你觉得
> 「界面没变」——所以自检里专门有一项在盯它（§10.2）。

```bat
scripts\make_icon.py                             REM 生成 exe 图标（改了图标绘制代码后要重跑）
.venv\Scripts\python.exe -m PyInstaller usbswitch.spec --noconfirm
```

产物在 `dist\USB Switch Console\`（onedir，约 130 MB）。

用 onedir 而不是 onefile：onefile 每次启动都要把整个包解压到临时目录，
冷启动明显更慢，而且自解压可执行文件更容易被杀软误报。

### 10.2 自检（打包产物的端到端验证）

窗口态 exe 没有控制台，所以自检把报告写进文件：

```bat
"dist\USB Switch Console\USB Switch Console.exe" --selftest --gui --json selftest.json
```

开发态等价：

```bat
.venv\Scripts\python.exe -m usbswitch --selftest --gui --json selftest.json
```

它会检查：**构建身份（产物是否落后于源码）**、路径解析、配置读取、DPAPI、
依赖导入（含 bleak 的 WinRT 后端）、UI 与 workers 全树导入、桥接服务起停、
磁盘检测、自启命令、图标绘制、**新版版面部件是否齐全**、主窗口离屏构建、
真实蓝牙扫描，以及（配置了远程时）真实建一次 SSH 隧道并探活。

其中两项是专门为「跑的是旧产物」这类问题加的：

| 检查项 | 它在防什么 |
|---|---|
| `build 身份 / 是否落后于源码` | 打包之后又改了源码。产物里记着构建时的源码时间戳，与当前源码树一比即可发现 |
| `主窗口离屏构建` | 不只验「窗口能建起来」（改版前后都能），而是**断言新版特有的 Hero 卡片存在** |

退出码 0 表示关键项全通过；`--json` 里的 `failed_critical` 列出失败项。

> 唯一能回答「**需要重新打包吗**」的地方就是这里。在没有源码树的机器上，
> 新鲜度那一项会如实跳过（无从比较），不会误报。

想额外验证「打包产物的开机自启确实指向 exe 本身」，加 `--autostart`：

```bat
"dist\USB Switch Console\USB Switch Console.exe" --selftest --autostart --json selftest.json
```

它会真往 `HKCU\...\Run` 写一次、回读校验、删除，然后**还原成进来时的状态**。
（不加这个开关就不会碰注册表。）

**改了打包配置或依赖后，请务必跑一遍这个自检**——开发态测试全绿、
打包后崩掉是这类项目最典型的失败方式。

### 10.3 测试

```bat
.venv\Scripts\python.exe -m pytest tests
.venv\Scripts\python.exe -m ruff check src tests --select F,E9
```

`ruff` 那条不是风格检查，是**查 bug**：它能抓到「引用了已被删除的名字」这类
单元测试极难覆盖的错误（曾经有一个只在「第二次启动」才炸的 `NameError`
躲过了全部测试）。

## 11. 已知限制

1. **远端桥接服务本身没有鉴权。** 默认经 SSH 隧道访问，所以它不必暴露在网络上；
   若你关掉隧道改用直连，请把远端主机放在可信内网并限制该端口的入站来源。
2. **隧道只在程序运行期间存在。** 程序退出后隧道随之关闭。
3. **Host 角色不可改。** Host A 恒为本机（Windows）、Host B 恒为远程（Linux）。
   本机桥接服务与远程桥接各只有一个端点，端口也只有一处。
4. **Windows 上两个基于 WinRT 的蓝牙客户端不能并发。** 所以本程序运行时不要
   再去跑 `scripts/usb_switch.py` 之类的脚本；网页面板走 Chrome 自带的 GATT
   实现，不受影响。
